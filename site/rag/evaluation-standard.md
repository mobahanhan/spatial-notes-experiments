# RAG 对照评测统一口径 v1

整理日期：2026-10-21（Asia/Shanghai）。

## 1. 原则与适用范围

**原 Bench 的定义优先；同一 Bench 内统一评分，跨 Bench 统一报告结构，不强行统一分数。**

本规范用于已保存的原版/当前版 1,200 个独立任务、2,400 份回答。它不意味着
这些回答已经完成所有官方评测，也不授权新的生成、付费裁判或并行 Agent。
原始回答、输入、参考答案、旧评分和原生源码均不覆盖，新口径产物另存。
这是在已观察部分结果后进行的口径统一，不是生成实验开始前的预注册，也不能宣称是独立盲测。

只对正式原版/当前版的四个批次计数：

| cohort | RGB | HotpotQA | CRAG | MTRAG-UN | FreshStack | 独立任务 |
|---|---:|---:|---:|---:|---:|---:|
| qa-original-current-100-20261019 | 60 | 20 | 20 | 0 | 0 | 100 |
| qa-supplement-100-20261019 | 0 | 0 | 0 | 60 | 40 | 100 |
| qa-additional-500-20261020 | 150 | 50 | 50 | 150 | 100 | 500 |
| qa-additional-500b-20261020 | 150 | 50 | 50 | 150 | 100 | 500 |
| 合计 | 360 | 120 | 120 | 360 | 240 | 1,200 |

qa-small 的 40 题已包含在首批 100 题中，不重复加入；其中 dense 方案不是历史原版。
SciFact 为独立的纯检索实验（300 题、三个方案），不加入问答通过率或新旧对照分母。

## 2. 三类结果必须分层

| status | 含义 | 允许的表述 |
|---|---|---|
| official_protocol_reproduction | 数据/语料范围、输入输出契约、评分器、裁判、截断、聚合等全部满足锁定官方设置 | 固定官方协议的复现结果；子样本必须明确标子集，不能冒称榜单全量 |
| official_metric_on_adapted_run | 指标公式/规则与官方定义一致，但生成或检索设置存在适配 | 官方指标定义下的本地适配实验，不是官方完整成绩 |
| local_diagnostic | 自定义词面分数、候选池来源覆盖、助手内容复核、JSON 合规等 | 本地诊断/补充复核，不得替代官方主指标 |

每个指标单独标状态，不给整个项目笼统贴“官方已评测”。缺失或尚未完成填 `null`
并附原因，不填 0。真正按锁定评分器得到的 0 原样保留。

当前五类 QA 均有不同程度的输入/候选资料/输出协议适配。对保存回答重评分，
不会把这些历史运行自动变成完整官方协议复现。

## 3. 各 Bench 的主指标

### 3.1 RGB

固定数据与现有源代码提交：`65ec39e40e7dc9abb50e9bf1b4f32be3f6f16615`。

- 抗噪声问答和信息整合：报告官方答案组命中/准确率规则。
  外层为必须满足的答案成分，内层为允许的别名；按官方代码处理大小写及中文空格。
- 负材料拒答：报告原脚本的拒答指标，以及需模型裁判的 Rej*（若实际完成）。
- 反事实鲁棒性：分别报告答案正确性、错误检测 ED/ED* 与纠正 CR；不能把只命中
  正确答案或只识别错误当成同时完成两个任务。CR 必须保留官方的条件分母。
- 按能力、语言、噪声比例、材料数量及正确资料比例分层；不同材料条件不混称同一实验。
- 官方基于特定文本标记的判定和 JSON `abstain` 字段不是同一规则。不得把已有
  布尔字段直接重命名成原生拒答率，也不得补写拒答句让已保存回答“通过”。
  如另设确定性协议映射，必须作为有版本的输出适配分支，不能冒称原始文本评分。
- 各子任务/语言汇总方式锁定并公开；自定义总体平均只能作补充，不能替代官方分项。

来源：[说明](https://github.com/chen700564/RGB/blob/65ec39e40e7dc9abb50e9bf1b4f32be3f6f16615/readme.md)、
[主评分](https://github.com/chen700564/RGB/blob/65ec39e40e7dc9abb50e9bf1b4f32be3f6f16615/evalue.py)、
[Rej*](https://github.com/chen700564/RGB/blob/65ec39e40e7dc9abb50e9bf1b4f32be3f6f16615/reject_evalue.py)、
[ED*/CR](https://github.com/chen700564/RGB/blob/65ec39e40e7dc9abb50e9bf1b4f32be3f6f16615/fact_evalue.py)。

### 3.2 HotpotQA

- 主报告完整保留 Answer EM、Answer F1。
- normalization 和 yes/no/noanswer 特例遵循官方 `hotpot_evaluate_v1.py`，
  不能使用自行选定的 F1 阈值转成“正确”。
- 支持事实 SP EM/F1、Joint EM/F1 只在模型确实输出官方所需的
  `(title, sentence_id)` 预测时计算。
- 当前记录里的检索片段、S 编号、参考支持事实、文本包含检测都不能充当模型预测的支持句。
  没有预测时完整 Joint 评测状态为“未采集”；不得事后把金标支持句填作预测。
- 长答案、解释、限定语必须保留在被评分的答案正文中，不让模型事后抽短答案提升 EM。

数据版本：`hotpotqa/hotpot_qa@1908d6afbbead072334abe2965f91bd2709910ab`，
distractor validation 共 7,405 题，当前子集 120 题。
执行前还必须固定评分脚本提交和文件 SHA；`master` 链接仅为查证入口，不视为已锁定。

来源：[官方评分脚本](https://github.com/hotpotqa/hotpot/blob/master/hotpot_evaluate_v1.py)。

### 3.3 CRAG

固定数据/评分源提交：`ad1518887dd4d9ebcd7de95388c7a62751e7705c`。

- 公开自动评分：correct +1、missing 0、incorrect -1。
- 同时报 `accuracy = C/N`、`missing = M/N`、`hallucination = W/N`、
  `score = (C-W)/N`，其中 `N=C+M+W`。综合分范围 [-1,1]，不叫“正确率”。
- 遵循锁定的 exact/invalid 判断、缺答识别、裁判提示与 tokenizer 截断规则。
  官方脚本含用 Llama tokenizer 截到 75 tokens 的处理；不得用字符切片替代后还称完全一致。
- `abstain=true` 不自动等于原生 missing，不能把所有拒答赋 +1；协议映射另列。
- 非精确匹配的模型裁判步骤不能用 Hotpot Token F1 或助手自定宽松规则替代。
  裁判型号、版本、参数、输入及原始输出均要记录；更换裁判标为替代裁判实现。
- 固定公开代码须先做离线测试。若为可执行性修复变量/调用错误，修复补丁、原因、
  行为等价测试与修复后哈希另存；不能悄悄更改评分含义。

采样共 120 题：前 70 题来自同一文件前 128 行，后 50 题来自完整 2,706 行公开文件。
两者属于不同采样范围，应分层报告；合并值仅为已选 120 题的描述性统计。

来源：[评测代码](https://github.com/facebookresearch/CRAG/blob/ad1518887dd4d9ebcd7de95388c7a62751e7705c/local_evaluation.py)、
[裁判提示](https://github.com/facebookresearch/CRAG/blob/ad1518887dd4d9ebcd7de95388c7a62751e7705c/prompts/templates.py)。

### 3.4 MTRAG-UN

数据/共享工具固定版本：`IBM/mt-rag-benchmark@53fef6f5917c7e10c436f697e69a955dbc795d81`。
当前公开四领域 507 个任务，实际子集 360 题，不包含未发布领域。

- 检索：保留官方 Recall@5/@10、nDCG@5/@10，按可答/部分可答的 qrels 适用范围计算。
  无 qrels 的题不能擅自当成检索错误，也不能当成检索正确。
- 生成：采用 MTRAG-UN 论文的 RB_llm、RB_alg、IDK、RAGAS faithfulness，
  按 answerability 处理；欠明确题使用专用 clarification judge，不能和其他题共用一个 F1 判据。
- 论文对应 GPT-OSS-120B 裁判；通用工具 README 的其他模型示例不等于该论文的精确设置。
  执行前还须锁定论文对应提示、依赖、聚合实现及模型版本，不能仅凭共享工具名称认定一致。
- 微平均、领域宏平均及加权平均必须分别命名；主表遵循锁定原生实现和论文对应口径，
  不将不同聚合方式互相替换。
- 当前是公开历史前缀 + 原生当前问题检索 + 候选资料池的适配运行。
  不是模型自行生成的完整多轮会话，也不是官方全库检索或原 Reference 设置的等价复现。
- 现有答案词面 F1/ROUGE、检索来源召回、`abstain`/问号标志只作为 local_diagnostic。
  它们不能冠名为 RB_llm、RB_alg、IDK 或 clarification judge 成绩。

来源：[论文 §3.1](https://arxiv.org/html/2602.23184v1#S3.SS1)、
[工具说明](https://github.com/IBM/mt-rag-benchmark/blob/53fef6f5917c7e10c436f697e69a955dbc795d81/scripts/evaluation/README.md)。

### 3.5 FreshStack

数据：`queries-oct-2024@023ac3a14caf9d6ebb13d01adcfb8fa05e5a9630`；
语料：`corpus-oct-2024@069f66dc323e163b48b10d08408d282733d4393b`。

- 原生主指标：α-nDCG@10、Coverage@20、Recall@50。
- 使用官方 nugget/query qrels、文档 ID 映射和排序；在完整规定语料中检索。
  不能把用于回答的若干压缩片段当作完整 top-50 排名，也不能用一个文档重复切块凑够 k。
- 保存每个领域的值；五领域宏平均单独呈现。另做样本微平均时明确注明，不能替换官方均值。
- 当前 240 题为每领域 48 题，且在抽样前排除超原生长度上限的问题。
- 现有标注候选池上的来源覆盖不等于官方 Coverage@20；新生成的文字答案 F1/
  助手回答通过率是本地 QA 扩展，不是 FreshStack 官方主成绩。
- 完整语料/排序若不在旧记录中，需要单独重跑检索并另存实验，不把新检索结果
  伪装成旧答案生成时所见资料；这与重新调用回答生成是两回事。

执行前需另锁定官方 evaluator 的提交、依赖及 SHA。
来源：[官方指标与排名](https://fresh-stack.github.io/)、
[工具与输入格式](https://github.com/fresh-stack/freshstack)。

## 4. 跨 Bench 统一的处理规则

### 4.1 原始数据与配对

1. 冻结四个批次的 cases.json、predictions.json 字节 SHA，验证每题恰有原版/当前版各一份。
2. 所有记录都保留；旧评分只读。疑似标签错误先按原生金标保留主分数，另做争议说明和
   敏感性分析。不得看到结果后静默删题、改金标或只保留有利样本。
3. 两版必须使用同题、同评分器、同适用条件及同分母；版本特有失败不能从该版分母中隐去。
4. 未完成的生成记录和未完成的评审各有独立状态，不当作答案错误；如官方实现存在失败回退，
   原生回退值与基础设施错误都记录，不能把回退冒称有效裁判结论。

### 4.2 输出适配

1. 只用预先声明的确定性适配；合法的约定 JSON 取完整 `answer` 正文，同时保留 raw_answer、
   abstain、citations。格式非法则保留完整原文，注明格式失败，不由另一模型“修复”答案。
2. 不根据金标删解释、改数字、补列表、提取“最有利短答案”，也不删除不确定性措辞。
3. 空正文、结构化 abstain 和自然语言拒答分别记录；不得悄悄填入官方检测关键词。
   如果某项官方判定无法和历史输出协议等价对应，标注适配偏离，并可附本地结构化行为指标。
4. 字段解包属于输出适配，不代表生成过程完整复现官方协议；文本合规与内容分数分列。

### 4.3 分层与聚合

- 相同评分口径必须覆盖首批、补充批和两批 500 题，不能用早期助手通过率替换后期原生 F1。
- generation cohort 必须保留：首批原生格式适配、补充格式适配、后两批 strict JSON Schema；
  首批中指纹核验复用的 40 条也保留来源，不能改称全部同一时间新生成。
- 对同一指标可附所有对应已选任务的题目加权描述性合并值，但不能说其消除了历史运行条件差异，
  不能从这些非随机样本推断总体显著改善。
- 不对不同 Bench 的 EM、F1、CRAG score、检索覆盖率求一个“总体正确率”。
- 比率默认存 [0,1] 并显示百分比；F1/nDCG 可存 [0,1]、显示 0–100，但差值称“分”，
  不是“正确率百分点”。CRAG 综合分固定 [-1,1]。
- 在同指标下显示原版、当前版、差值、n/适用 n、cohort、范围、完成状态。
  方向性和置信区间若提供，使用同题配对方法；单次小样本不宣称统计显著。

### 4.4 助手内容复核是补充，不替代原生评分

若后续获准开展，将原版/当前版随机匿名化，按固定规则逐题复核；也重新检查早期 200 题。
允许同义答案，但不替模型补足缺失的核心事实；按原任务区分回答、合理拒答、适当澄清；
无根据矛盾或实质性错误不得判通过。参考存在争议时保存理由并交叉核查。

结论名为“本地内容复核通过率”，记录评审者及是否真正独立盲评，不叫官方准确率。
同时保留官方金标原分和争议敏感性统计，不用这一补充结果重写官方评分。
未经明确授权，不启动并行 Agent、不使用用户 API 账户运行付费裁判。

## 5. 标准报告结构

固定三张表，不混在一列：

1. **原生指标表**：Benchmark / 子任务 / metric / 原版 / 当前版 / 差值 / n /
   applicable_n / scope / cohort / implementation / status。
2. **数据质量与覆盖表**：已生成/计划、可评审/待评审、裁判失败、格式失败、缺失字段、
   争议题、源记录去重、采样范围、评测资料范围、实际裁判用量。
3. **补充诊断表**：词面 F1/ROUGE、候选池来源覆盖、本地内容复核，明确 local_diagnostic。

每行保留结果文件、source/prediction SHA、规范版本、scorer/依赖哈希、judge/config/prompt
版本及明细路径。judge/model 的身份和用量只能按实际返回/证据表述，不虚构底层证明或账单。

## 6. 当前能够与不能够完成的事项

| 项目 | 现有记录的适用情况 |
|---|---|
| Hotpot Answer EM/F1 | 可按统一官方定义从保存的答案重算；仍属本地适配子集 |
| Hotpot SP/Joint | 未采集官方格式的预测支持事实，不能事后用金标补齐 |
| RGB 答案组分项 | 可重算规则定义；拒答/ED/CR 还需按文本契约与对应裁判分开处理 |
| CRAG 完整自动分 | 需锁定可执行评分器、75-token 处理、缺答规则及裁判；F1 不能替代 |
| MTRAG-UN 原生生成分 | 需论文对应裁判/算法、材料、条件处理；旧词面分不能换标签冒充 |
| MTRAG-UN 官方全库检索分 | 当前候选池记录不能等价恢复全库实验 |
| FreshStack 主指标 | 需完整规定语料与原生排序；现有候选池 QA 记录不足以冒称完成 |
| SciFact | 另表保留已完成纯检索实验及明确 k，不当作历史原版问答对照 |

整理本规范不等于上述缺失评测已完成。新费用、裁判型号替代、补跑检索或重新生成均应明确
说明范围和预算，不沿用过去已经耗尽/结束的生成授权。
