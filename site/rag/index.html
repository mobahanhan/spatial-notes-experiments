环节原版实际设置当前版实际设置
运行代码来自修改前归档的原版实现；保留原生切分、HF 嵌入、FAISS 检索与问答提示词。重构后的 myrag 模块；不是把旧代码换一个名称。
原材料同一题使用相同的冻结候选文段。不是两版分别挑材料，也不是 Benchmark 全量语料；标签、答案与相关性标注不进入检索索引。
分块算法RecursiveCharacterTextSplitter；按段落、换行、空格递归分割；每个输入页面独立切分。page-boundary-v1；页内滑动窗口，在后半窗口优先寻找换行、中文标点、英文句号空格、空格等边界。
分块参数最大块长 1,000 字符，重叠目标 200 字符，不是 Token 数。参数相同不代表切出的块相同。
运行时分块从冻结 chunks 无缝恢复候选页面，再用原版算法切分。网页展示实际保存的原版索引片段，不用新切分器替代。直接使用预处理时冻结的 chunks，不在答题时重新切分。
定位元数据原始索引有来源、页码、片段正文和索引 ID，没有保存字符位置；网页额外的唯一原文匹配定位会注明为派生。原始记录保存稳定 chunk ID、source、page、start/end。字符位置以 Unicode 码点计数，左闭右开。
嵌入模型同一 shibing624/text2vec-base-chinese 与固定 revision 183bb99aa7af74355fb58d16edf8c13ae7c5433e。没有更换更强的嵌入模型，也没有在这些题上训练。
向量与距离原 HuggingFaceEmbeddings 默认输出，不额外归一化；FAISS IndexFlatL2。归一化向量；FAISS IndexFlatIP，相当于余弦相似度；另检查零向量和非法数值。
召回、融合与去重单路向量检索，返回前 3 块。向量与 BM25 两路各最多 12 个候选；RRF 权重各 0.5、常数 60，融合最多 12 个；按来源/页码/区间去重，选 3 块。不是直接相加 BM25 与余弦原始分数。
BM25 分词没有这一路。NFKC 规范化；英文与标识符分词；中文单字及重叠二元词；k1=1.5，b=0.75。
证据窗口将检索得到的原始块放进上下文。按查询词匹配选择最多 3 个重点句，再保留邻句、合并连续区间；没有词面匹配时保留原块。不调用模型改写。一个 chunk 可产生多个窗口，所以返回窗口数可以大于 3。
上下文预算格式化原生前 3 个片段，没有当前版的 6,500 字符证据预算逻辑。证据正文总预算 6,500 字符；保留实际截取区间。格式、问题和系统提示不等于这个证据正文预算。
提示词与角色原生问答模板作为 user 消息；使用页码引用，且包含“来自同一篇文档不同页”的假设，这对多来源任务可能不合适。system/user 分离，EVIDENCE_JSON 与 S1、S2 引用；明确文档/历史不构成系统指令，历史用于消解指代，不作新证据，要求按问题语言回答。
答题模型使用同一 GPT-6.1 Sol 调用通道与共享输出上限/低推理强度；模型名称按服务返回记录，不据此独立证明底层型号。不是换答题模型带来的对比。
可追溯记录原生来源列表、实际索引；大部分调用输入保存，最早复用的 40 份当前版输入未保存。额外有逐路召回 ID、融合候选、最终选择、区间与引用诊断。页面的当前版检索轨迹来自保存记录，不是事后重跑。

共享适配与批次差异

两版都直接接收公开文本，而非重新跑 PDF/OCR；共享模型通道、最多 1,024 个输出 tokens、低推理强度，以及 JSON answer / abstain / citations 契约。补充批和后两批按同一方式向两版提供已发布历史前缀；后两批额外使用 strict JSON Schema。首批、补充批及后两批的格式说明位置/约束有差异，不能说所有 1,200 题都在完全相同的生成协议下运行。

批次题数输出与历史适配
首批（含最早 40 题）100保留原生提示词并追加共享 JSON 格式；40 份当前版复用回答经指纹核验，不重复计数。
补充批100共享格式说明及已发布历史前缀；没有 API 侧 strict JSON Schema。
追加 A / B500＋500共享格式说明放在最后一条 user 消息末尾，使用 API strict JSON Schema；历史按相同方式提供给两版。

代码支持，但本次未启用

当前项目支持 CrossEncoder 重排序、证据充分性检查、缺口驱动补检索和停滞停止，但这 1,200 条当前版保存的检索轨迹均只有一轮，reranker 为空，没有证据检查器记录。这些能力不能写成本次已验证的提升来源。此处的“证据检查器”也不是后续用于评分的裁判。

工程变化，不冒充已测能力提升

常规应用还改为模块化检索接口、不可变 FAISS＋JSON 版本快照、构建原子切换、模型/分块配置指纹和更明确的错误处理。旧持久化方案依赖 docstore pickle；当前存储不读取 pickle。不过这次当前版 QA 使用内存快照，并没有通过这些工程改动测得回答能力提升。

结论边界：切块、向量距离、检索、证据处理与提示词同时变化。这是整套流程的配对比较，不是单因素消融，不能把结果变化单独归因于某一项。

原生评分，不做事后答案美化

合法的约定 JSON 取完整 answer 正文；格式不合规则保留完整原文。不会根据参考答案删去解释、抽取有利的短答案、修复 JSON，或补写拒答关键词。布尔 abstain 不等于原生自然语言拒答。

RGB
抗噪声、整合、反事实回答按答案组规则；拒答采用 Rej*。反事实还需分别观察 ED* 与 CR*；CR* 只以检出的错误为分母。题目颜色不代表所有反事实子能力均通过。
HotpotQA
完整保留 Answer EM 和 token F1。没有模型预测的 (title, sentence_id) 支持事实，SP/Joint 不可计算；不以任意 F1 阈值定义“正确”。
CRAG
correct +1、missing 0、incorrect −1；同时报告正确率、缺答率、错误率与综合分。使用锁定的 Llama tokenizer 进行 75-token 处理，再按原生规则和替代语义裁判判定。
MTRAG-UN
按 answerability 进行拒答/澄清门控，再报告条件处理后的 RB_llm、RB_alg 与 Faithfulness。它们是连续指标，不是答对题数。主表使用样本加权均值，四领域等权宏均值单列。
FreshStack
原生指标是 α-nDCG@10、Coverage@20、Recall@50。历史候选池 QA 没有官方全库排名，因此只能展示问题与回答，不能虚构官方检索成绩。

缺失与适配边界

五类实验均存在输入、候选资料或输出协议适配，因此属于“原生指标定义下的本地适配实验”，不是官方完整协议复现。涉及模型裁判的部分使用服务返回标识为 GPT-6.1 Sol 的替代裁判，并非历史论文裁判的精确复现。

标准是在看到部分结果后统一的，不是预注册独立盲测；生成与裁判属于同模型家族，存在自评偏差。单次非随机子样本的差值不证明总体或统计显著提升。缺失指标保留未采集，不填 0。

少数最早复用回答没有保留下实际调用的完整输入，页面明确标注缺失，不从参考答案或新代码补造。本页“检索材料”来自保存的返回片段；“模型输入”显示经指纹校验的输入原文，两者不会混称。
