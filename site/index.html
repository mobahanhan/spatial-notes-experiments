一、背景

空间智能需要拥有“感知-行动”的主动探索能力，具体来说，空间智能需要通过“行动”改变自己在环境中的位置、视角，从而感知到新视角下的信息，以此规划并输出下一步的行动，进而获取足够的信息完成任务。与非主动探索的任务不同，主动探索的任务一般包括在未知环境下根据已获得的信息，识别并揭示尚未被看到的内容，如存在遮挡物的环境下的物体寻找、通过实际探查来判断两个区域是否连通或是否能相互到达等等。这类任务一般在 3D 引擎（如 Isaac Sim、Unity 和 Unreal Engine）上进行仿真，AI 首先被告知要执行一个特定任务，由摄像头拍摄当前图像，通过特定接口输入智能体，智能体以此进行推理，并在特定的动作集中执行允许的动作，引擎中的摄像头也会做出相应的位姿变化，并将下一张图片输入智能体，直到智能体认为自己完成任务之后为止。

我们在 ESI-BENCH 中选择了特定的题目来对 gpt-5.5 进行测试，发现其在以上问题中的表现极其不理想。在大部分情况下，智能体无法做出的有逻辑的行为，其输出的指令近乎随机，无法对未知的环境进行有效的探查，自然也无法完成相应的任务；还有一部分情况是，AI 在对环境做出象征性的探究后，便以极高的自信或常识做出回答，实际上它并未搜寻到关键的证据，也并没有主动探索盲区的“欲望”，即使有时能够猜对答案，也是碰巧蒙对，并非是通过有逻辑的证据链得出。

我们首先探究了这种问题的发生是否是由提示词不充分造成。于是我们为每个题目定制了相应的带有明显提醒与暗示功能的提示词，包括物体的大小、要采用空间的方法探究而非常识推断等等，然而并未发现明显改善。

接下来有两个改善该问题的研究计划：

  • 通过特定的策略的Harness来改善问题，比如规定如何才算合适的视角、绕障的方法、记忆的维护等等
  • 通过构造特定的数据来对模型进行训练

现在的研究是在执行前者。

二、相关工作

被动空间理解

如 SpatialRGPT、Omni-View、Spatial-MLLM、S-Agent 等，给定 VLM 固定的单个图像、多视图图片或视频，令其直接通过图片分析、或者重构三维结构后分析，并回答如两个指定区域的左右、前后、远近、距离和复杂空间关系等几何性质的空间问题。这类工作不能通过由模型主导的环境动作获取新的信息，它们接受完整的空间信息或从图像、视频中提取空间结构并进行推理，并非主动探索与主动信息的获取。

具身相关的空间探索方面的工作

如 Embodied-Reasoner、SCOPE。在这些工作中，智能体需要根据任务主动探索未知的环境，而探索的方式又有不同。Embodied-Reasoner、SCOPE 都允许模型输出如“探索某处”“切换位于某处的视角”这样的宏观层次的动作，但是将大量底层运动（如向上、向下等）封装进高层接口，并不以在具体底层动作层次上如何操作为重点。以上工作虽然包括“主动探索未知”的部分，但是在空间智能体输出“行动”时更加倾向于“探索某处”的宏观的、语义上的概念，而非是空间能力相关的具体动作与视角姿态的变化。

真正与该工作强相关的测试集

  • ESI-BENCH，一个具身空间智能 Benchmark，主要包含无法仅凭被动观察回答，需要判断应调用哪些能力（感知、移动、操纵）、采取哪些动作（移动到哪里、探查什么、如何操纵），以及按怎样的顺序执行这些动作，才能成功回答的问题。
  • E3VS-Bench，用于评估 3D 环境中依赖视角的推理和主动感知能力的测试集。智能体必须主动控制其在 3D 空间中具有完整 5-DoF 的视角，以获取与任务相关的视觉证据来进行问答。

其中的大量问题与本项工作“主动探索未知，并输出具体动作”的能力需求强相关。

OmniNav

OmniNav 维护三维地图与历史观察记忆，分为两个模块：一、慢速模块：负责较长范围的规划，它结合历史观察、空间记忆、语言记忆、探索范围，选择下一处探索目标，并把复杂任务拆成子任务；二、快速策略：生成以平面位置 + 朝向表示的连续导航寻路信息，并在三维环境中评测导航成功率与路径效率。疑似与本项目有一定相同点。

三、方法

思想

根据经验，在判断某个空间问题时（目前主要研究的是计数类问题），最直接的思想是先环视一周，锁定周围可见目标以及不可见区域的位置，然后探索不可见的区域。本Harness正是依据此来完成。

GPT-6.1 的实验结果也表明，在部分成功的任务中，也确实是先完成了环视探索，说明此方案有一定的合理性，可以为此策略提供启发。不过关于它是如何确定盲区并精准定位物体的，由于没有 CoT，并不能简单确定。

方案

一、探索状态机

这个状态机代表人类要求智能体探索的思路，初始观察 >> 盲区探索 >> 验证盲区 >> 重新探索。

初始观察包括：一、初始视角的调整，首先，以摄像头初始的视角是正常的为目标，尝试改善摄像头的观察高度，目的是希望初始视角没有面对某个限制视角的区域，如近距离的墙壁、地面、角落等等；二、八个方向 + 地面的旋转探索，摄像头向 8 个方向旋转，每次旋转 45°，覆盖 360° 的视野，最后转向地面，防止摄像头过高导致遗漏贴近正下方的目标；三、根据盲区的位置，尝试绕过障碍物，观察到盲区后的情况（；四，某个盲区被确定观察完毕，回到第三步；五、在所有被智能体发现的盲区被探索完毕后，输出一个确切的答案。

注意，在测试时使用的是 30 步的步骤预算，用光之后自动输出答案。

二、输出的形式与记忆

模型被输入的就只有当前视角的图片、题目、合法动作、近期执行反馈、剩余预算、探索的方向覆盖情况及状态机的当前状态。它的输出包括：

  • belief：对当前环境的理解，包含 facts、objects、hypotheses（分别是根据已观察到的内容，生成的智能体认为的，带有不同水平可信度的事实情况、物体与假设）、blind_regions（尚未探索或被遮挡的区域，有不同的探索优先级）。
  • candidate_actions ：模型打算输出的候选动作指令，通过多个维度的评估来确定它的权重。
  • selected_action：模型提交的最终动作。
  • answer 与 confidence：模型输出的问题答案与置信度。
  • reasoning：模型输出的推理过程。
  • stop_requested：模型认为搜集信息已经完整，请求停止的信号。
  • navigation_plan：处理探索盲区的方式的模块。

三、探索盲区的方式

当前探索盲区的方式较为单一，采用旋转绕行的思路。对于在前方的盲区，我们先向水平方向横移，寻找能绕至遮挡物一侧的水平位置，这一步由模型判定在什么方向绕行更加合适；在完成横移之后，下一步是前进，穿过遮挡物的侧面，然后转向，看向遮挡物的后方。

然而，目前的结果是，即使加入了这个探索盲区的方式，模型只是机械地执行它，并没有很好地根据实际情况来调整执行这一串的探索步骤的策略。

四、结果

目前的实验结果证明，简单的空间提示对模型的正确率并没有明确的提升。对于当前 Harness 的情况，目前的实验表明，在初始视野未受限的情况下，模型并不擅长根据目标将视角调整至合理的位置，即使象征性地做了，也没有保证视角是正常的，经常周围探索一圈了还有漏看的区域；关于如果模型一开始的视角是受限的将如何调整，尚缺乏验证；关于探索盲区的步骤，模型经常在“八个方向 + 地面”的粗略探索之后不重新定位目标，也没有在探索的过程中随时判断当前视角是否合适，只是机械地执行当前 Harness 给出的指令。

所以也不能证明目前的 Harness 能对空间问题的能力提升有任何帮助。
